# Week-8-CS-250
To turn user needs into a program, I first try to understand what the user really wants to achieve, not just what they say. Writing user stories helps because it breaks down requirements into clear goals from the user’s point of view. By focusing on user stories instead of technical features, I can keep my attention on what the user needs and why, which makes it easier to design something helpful.

When I develop programs, I like to break tasks into smaller steps and focus on each part one at a time. During this course, I found Agile methods helpful, especially working in short cycles, updating features after getting feedback, and staying in touch with the team. Going forward, I plan to keep using user stories, building in small steps, and testing often because these approaches help me adapt when requirements change.

To be a good team member in software development, I think it’s important to communicate clearly, be dependable, and listen to feedback. Working well with others, asking questions when I’m unsure, and helping the team are all key. Teams do their best when everyone is on the same page, ready to adjust, and focused on building a quality product together.
